# R1 GUI/desktop design v1 — findings (read-only)

Read-only investigation; only this doc written. kernelhwsrv/ untouched; no make/QEMU run.

- **Current state:** no GUI/desktop/browser (`PROJECT_GOAL.md:45` "Web browser — Not started"). Only an 80x25 text-mode VGA teletype at phys 0xB8000 + COM1 mirror (`console/vga.{h,cpp}`, `variant/genuine_console.cpp`, `variant/kern_shell.cpp`) and a PS/2 Set-1 keyboard ring. No framebuffer/SVGA/VBE, window server, fonts/bitmaps, compositing or mouse. Both launchers (`tools/r1_qemu_smoke.py:144-156`, Makefile `kernfull`:339 / `qemu`:536) boot `-display none -serial stdio`; **no `-vga` flag** (default SeaBIOS VGA text only).
- **Kernel/display gap:** `kernelhwsrv/.../kernel/x86/ckernel.cia` is pure asm thread-entry + exception-trap glue (no video); no `qemu_k.cia` exists. `K::InitHalEntryArray` (`sinit.cpp:552-559`) registers HAL groups 0/1/3 only — group 4 (EHalGroupDisplay) unregistered, so `UserSvr::ScreenInfo` returns KErrNotSupported. `r1-console/README.md:67-73`: 80x25 is text cells, not a bitmap resolution; no ProcessDisplay* provider. QEMU variant only does PIC/PIT/COM1/RTC/VGA-text; no graphics function in `qemu_variant.h`; upstream `drivers/display/display.cpp`, `drivers/edisp/epoc/vga/vgatext.cpp` (0xA0000+0x18000), `ewsrv/ws_main.cpp` (gates ESHELL.EXE on `UserSvr::TestBootSequence()` at :2166) are NOT in KERNFULL_OBJS (Makefile:274).
- **EUSER graphics ordinals** (`kernelhwsrv/kernel/eka/bx86gcc/euseru.def`, 2503 exports = loaded EUSER.DLL): `UserSvr::ScreenInfo @1211`, `HalFunction @1213` (+5-arg @2005), `RequestEvent @1216`, `CaptureEventHook @1220`, `ReleaseEventHook @1222`, `WsRegisterThread @1225`, `WsSwitchOnScreen @1226`, `RequestEventCancel @1227`, `WsRegisterSwitchOnScreenHandling @1231`, `AddEvent @1235`, `TestBootSequence @1224`. No CFbs*/CWsScreen*/RWindow graphics ordinals here; `CBitMapAllocator` (~@435-457) is allocator-only.
- **IPC (user<->kernel):** exec2/exec4 fast/slow executives; `user/ipc.c` is a genuine ABI bridge — server_create 126, connect 128, SessionSend 77, ServerReceive 34, MessageComplete 65, MessageIpcCopy read/write8/16, ChannelRequest 10 (PortCon/PortFile LDC/PDD), HandleClose 106, async completion via request semaphore exec 58. `user/runtime.c` adds chunks (global named RChunk, exec 107/109/108) for shared memory — sufficient to carry display shared buffers.
- **Needed / next steps (all in qemu-port/):** (1) pass `-vga std` (optionally VBE) in smoke + Makefile and enable a visible display; (2) register an EHalGroupDisplay handler answering ScreenInfo/mode/WsRegisterSwitchOnScreenHandling; (3) add a VBE linear-framebuffer driver + shared global chunk (RChunk) with font/bitmap blit; (4) add PS/2 mouse and route input via `Kern::AddEvent`/WsRegisterThread; (5) stage genuine EWSRV/EDISP/FBSsrv/ESHELL on the IPC bridge and fix the TestBootSequence gate; (6) build a GUI shell/file manager, then the web browser over the window server + TCP/IP stack. No kernelhwsrv changes required.

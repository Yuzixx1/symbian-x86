## 6. UID3/SID/VID/caps — placeholders (E32-specific fields)

They are set during petran PE→E32 conversion. The current PE executable does not
carry them. They will be populated from the emitted E32 image after petran

## 9. Petran PE→E32 conversion — follow-up blocker

petran was not built in this session. Attempted to compile petran sources from
`r1-build-v1/src/build/bintools/petools/` with MinGW 3.4.5 under Wine, but hit
MinGW header compatibility issues:

| Issue | Detail |
| --- | --- |
| `strstream.h` not found | Deprecated header removed from MinGW 3.4.5 `<new>`/stdlib; used by `imgtools/imglib/inc/h_utl.h` |
| `operator new[]` redefinition | Symbian `e32cmn.inl` placement new conflicts with MinGW `<new>` definitions |
| `__gnuc_va_list` undeclared | Include-order interaction when forcing `-include new` |

The `r1_build_repro_v0.md` (D7) notes petran was built successfully with
hand-assembled flags including `-include new`, but additional workarounds were
needed that were not fully documented. Building petran is a separate task that
requires these workarounds to be resolved.

**Recommendation:** Build petran as a separate step (documented workarounds from
D7 plus strstream.h compatibility shim), then run:
```
wine petran.exe -sid <uid3> -uid <uid1> <uid2> <uid3> -capability <caps> \
  -stack <size> -heap <size> bin/portfilesrv.exe bin/portfilesrv.e32
```
to produce the E32 image, then re-audit UID3/SID/VID/caps from the E32 header.

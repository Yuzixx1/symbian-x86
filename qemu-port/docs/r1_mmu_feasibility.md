# R1 M-03 MMU + user isolation — feasibility (read-only, 2026-11-20)

Current state (verified)
- Boot MMU: `mmu/mmu_gas.S` `qemu_page_dir` 4K BSS; `Mmu_BuildIdentityMap()` writes 1024×4M identity PDEs P|W|PS|G, U/S=1 for idx<512 (<0x80000000), U/S=0 high half; `Mmu_Enable()` loads CR3 + CR0.PG|WP + CR4.PGE once in `kernfull_glue.cpp:HwInit0` (bridge twin `qemu_kernel.cpp`). No page tables.
- Per-process PD is port-side only: `mmu/pd.{h,cpp}` 16-row `DProcess*`→{4K PD of 1024×4M copies, code/data/stack runs}; `e32load.cpp:805` PdCreate after ProcessCreate, `:1047` PdDestroy in E32Reap. `pd.o` links only into `KERNFULL_OBJS` (Makefile:274), not default `make all` (BRIDGE_ELF:500).
- CR3 switching now wired: `PdInit()` (`kernfull_glue.cpp:102`, before `X86::Init1Interrupts` builds the IDT from `TheExcVectors` in `cinit.cpp:85`/`vectors.cpp:113-121`) installs naked `PdProcessSwitch` via public `TScheduler::SetProcessHandler` and a Vec14 stub; `e32load.cpp:50,896` tags each DThread's `iNThread.iAddressSpace`=PD + KThreadAttAddressSpace bit; genuine `ncsched.cia:181-184` fires the handler, `:175-179` reloads TSS.esp0 per thread.
- #PF contained port-side: `pd.cpp` `PdPageFaultStub`/`PdPageFaultC` decode CR2+error bit2 → `K::PanicKernExec` (user) / `Kern::Fault` (kernel). Genuine `TPagingExcTrap` (`ckernel.cia:331-399`) compiled but unused.
- U/S only coarse: 4M PDE split at 0x80000000; kernel heap/stacks/TSS/trampolines below it stay U/S=1 → no real isolation. Direct memmodel (Makefile:71); `DProcess` has `iCodeSeg`/`iDataBssRunAddress`/`iDataBssStackChunk` (`kern_priv.h:1706-1708`) but no PD slot; `execs.txt` has no MMU-control execs.

Verdict: **Feasible purely in qemu-port/ — no kernelhwsrv/ edits needed.** All hooks are already public there (`SetProcessHandler` nk_priv.h:315, `SetAddressSpace`/`ModifyAttributes` :240-245, `iAddressSpace` :260, `TheExcVectors` vectors.h:20, per-thread TSS.esp0 ncsched.cia:179); single CPU needs no ASID/PCID, full CR3 flush is acceptable.

To finish M-03 (all qemu-port/): (1) `mmu_gas.S`/`pd.cpp`: replace 4M PDEs with copied kernel 4K PTEs U/S=0 + on-demand 4K PTs mapping user code/data/stack U/S=1 from a kernel/fixed 4K pool; (2) `e32load.cpp`: whitelist/relocate ring-3 trampolines + resident EUSER in kernel heap (else they fault) and tag threads created after E32Run; (3) upgrade `PdPageFaultC` to deliver an EKA2 exception to the owning thread instead of a blanket panic; (4) `Makefile`: link pd.o into the default image; add CR3/fault serial trace.

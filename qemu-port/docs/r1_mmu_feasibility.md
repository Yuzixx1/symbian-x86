# R1 M-03 MMU + user isolation — feasibility (read-only, 2026-11-19)

Current state (verified)
- Boot MMU `mmu/mmu_gas.S`: `qemu_page_dir` 4K BSS, `Mmu_BuildIdentityMap()`=32×4M identity PDEs 0x83/0x183 (P|RW|PS|G, **no U/S=0**), no PTs; `Mmu_Enable()` loads CR3, CR0.PG|WP+CR4.PGE once in `variant/qemu_kernel.cpp:41-54` before `KernelMain()`. One flat AS; `mmu.cpp` TouchTest only.
- Per-process PD is port-side bookkeeping: `mmu/pd.{h,cpp}` = 16-row `DProcess*`→{4K PD, code/data/stack runs} table; PD = 32×4M PDEs 0x87 (U/S=1) but **never loaded**. Seeded at `e32load.cpp:785` PdCreate / `:1026` PdDestroy; `pd.o` links only into `make kernfull` (Makefile:271), not default `make all` (BRIDGE_ELF:397).
- **CR3 never switched**: `%cr3` only in mmu_gas.S (boot/status) + shell read; no PdSwitch. Harness `nk/nk_ctx_gas.S:NThread_Switch` saves CR0/fs/gs/regs/EIP only, and is retired from the full link (Makefile:494-496) — real ring-3 DThreads run on genuine `ncsched.cia`. TSS.esp0 *is* reloaded per thread there (`ncsched.cia:175-179`, `X86_TSS_Ptr->iEsp0 = iStackBase+iStackSize`); `e32load.cpp:TssInitOnce()` only publishes the TSS.
- **No #PF containment**: bootstrap Vec14→`VectorCommon` prints "bootstrap FAULT vector=0xE"+`hlt` (bootcpu_gas.S:335,436-457); genuine IDT Vec14=`TheExcVectors[14]` but no process-aware handler. `TPagingExcTrap`/`TExcTrap` (ckernel.cia:170-399) compiled, never wired to #PF; the real page-fault decoder lives only in unbuilt `memmodel/epoc/multiple/x86/xkernel.cpp:181`.
- **No U/S enforcement**: 4M PDEs only; no 4K PTs, no kernel/user split. `DProcess` (`kern_priv.h:1706-1708`) has `iCodeSeg`/`iDataBssRunAddress`/`iDataBssStackChunk` but no portable PD slot (only flexible model adds `iPageDir`/`iOsAsid`) → side-table is right. `execs.txt` has no MMU-control execs (only chunk/memory-info queries).

Verdict: **Feasible without editing kernelhwsrv/.** The genuine scheduler already exposes the needed hook: `TScheduler::SetProcessHandler()` (public, `nk_priv.h:315`), fired from `ncsched.cia:181-184` when a thread has `KThreadAttAddressSpace=2` (`nkern.h:675`) in `NThread.iSpare2`; the naked handler gets EBX=NThread and should `mov cr3,[NThread.iAddressSpace]` — exactly the unbuilt `multiple/x86/xsched.cia:20-44` reference. All setters (`SetAddressSpace`, `SetAttributes`/`ModifyAttributes`) are public inline. No asm patching of read-only code needed. Single CPU ⇒ no ASID/PCID (full CR3 flush OK).

Remaining work (all qemu-port/): (1) `mmu/pd.cpp`: replace flat PDEs with copied kernel mappings + on-demand 4K PTs, U/S=1 user / U/S=0 kernel, add `PdMapUser` and a naked `PdSwitch` handler; (2) `e32load.cpp`: after ProcessCreate tag each DThread's `iNThread` (SetAddressSpace(proc)+ModifyAttributes(0,2)) and install handler once via SetProcessHandler — also tag later-created threads; (3) new port-side Vec14 stub (CR2+error decode) → kill owning thread on user CR2, `Kern::Panic` on kernel CR2; (4) `variant/qemu_kernel.cpp`/`kernfull_glue.cpp` install #PF+before first user proc, add CR3/fault trace; (5) `Makefile` link pd.o into default make.

Caveat: pilot trampolines and resident EUSER code live in RWX kernel heap (`e32load.cpp:46-66,551-609`); marking all kernel pages U/S=0 would fault them — whitelist/relocate those pages, or use the ≥0x80000000 split plus user-range mapping.
